**Версия:** 1.0  
**Дата:** 26 июля 2026  
**Автор проекта:** Хику  
**Тип продукта:** No-code конструктор сайтов с фокусом на автономный экспорт

## 1. ОПИСАНИЕ ПРОЕКТА

### 1.1. Концепция
Веб-платформа для визуального создания одностраничных и многостраничных сайтов с возможностью экспорта в виде:
- **Single HTML файла** (полностью автономный, работает офлайн)
- **ZIP-архива** (структурированный проект для хостинга или доработки)

### 1.2. Ключевое отличие от конкурентов (USP)
**Полная автономность и отсутствие Vendor Lock-in.** Пользователь получает готовый код, который:
- Работает без интернета (при открытии через `file:///`)
- Не требует хостинга или подписки
- Может быть отправлен клиенту как файл
- Может быть размещен на любом хостинге

### 1.3. Целевая аудитория
- Фрилансеры и веб-разработчики (быстрый прототипинг)
- Маркетологи и менеджеры (создание коммерческих предложений)
- Дизайнеры и фотографы (портфолио для отправки)
- Корпоративные пользователи (внутренние инструкции, базы знаний)
- Студенты и спикеры (презентации в формате сайта)

### 1.4. Основные сценарии использования
1. **Direct-Share сайты:** Отправка готового HTML-файла клиенту в мессенджере или на почту
2. **Локальные презентации:** Выступление с сайтом как с интерактивной презентацией
3. **Офлайн-документация:** Создание инструкций, которые работают на компьютере без интернета
4. **Быстрый прототип:** Создание макета сайта для передачи разработчику

## 2. АРХИТЕКТУРНАЯ КОНЦЕПЦИЯ

### 2.1. Хранение данных
Сайт хранится в базе данных **не в виде HTML**, а в виде **JSON-дерева компонентов (AST)**.

**Пример структуры JSON:**
```json
{
  "projectId": "uuid-123",
  "globalSettings": {
    "fonts": { "primary": "Inter", "fallback": "sans-serif" },
    "colors": { "primary": "#0066cc", "background": "#ffffff" },
    "globalHeader": { "blocks": [...] },
    "globalFooter": { "blocks": [...] }
  },
  "virtualPages": [
    {
      "id": "page_home",
      "slug": "home",
      "seo": { "title": "Главная", "description": "..." },
      "blocks": [
        {
          "type": "section",
          "id": "block-1",
          "styles": { "padding": "40px", "background": "#f5f5f5" },
          "children": [
            {
              "type": "heading",
              "content": "Добро пожаловать",
              "styles": { "fontSize": "48px", "color": "#333" }
            }
          ]
        }
      ]
    }
  ]
}
```

### 2.2. Рендеринг
Отдельный модуль (рендерер) преобразует JSON в HTML/CSS:
- **На фронтенде:** Для предпросмотра в редакторе
- **На бэкенде:** Для генерации финального экспорта

### 2.3. Принцип "Offline-First"
Все экспортируемые сайты должны работать **без подключения к интернету**:
- Шрифты встраиваются в CSS (Base64)
- Иконки встраиваются как SVG или Base64
- Картинки опционально встраиваются или сжимаются в WebP
- JavaScript работает локально (без внешних библиотек с CDN)

### 3.2. Модуль: Визуальный редактор (Canvas)

#### 3.2.1. Интерфейс редактора
**Трехколоночная структура:**
- **Левая панель (250px):** Библиотека блоков, панель страниц
- **Центр (Canvas):** Визуальный холст с превью сайта
- **Правая панель (300px):** Настройки выбранного блока, глобальные настройки

#### 3.2.2. Система виртуальных страниц (Multi-Page in One File)

**Панель управления страницами (слева сверху):**
- Список всех виртуальных страниц с возможностью:
  - Создать новую страницу
  - Переименовать страницу
  - Изменить slug (URL-якорь, например `#services`)
  - Удалить страницу
  - Перетащить для изменения порядка
- Переключатель активной страницы (табы)

**Сквозные блоки (Global Sections):**
- **Header:** Автоматически добавляется на все страницы
  - Содержит навигационное меню
  - Меню автоматически генерирует ссылки на все виртуальные страницы
  - Редактируется один раз, применяется ко всем страницам
- **Footer:** Аналогично Header

**Изоляция контента:**
- При переключении между страницами на холсте отображается **только контент выбранной страницы**
- Пользователь не видит "кашу" из всех блоков сразу
- Визуальный индикатор: "Вы редактируете страницу: Услуги"

#### 3.2.3. Библиотека блоков (Базовый набор для MVP)

**Структурные блоки:**
- **Секция (Section):** Контейнер с настройками фона, отступов, максимальной ширины
- **Контейнер (Container):** Внутренний контейнер для группировки элементов
- **Колонки (Columns):** Flexbox/Grid сетка (2, 3, 4 колонки)
- **Разделитель (Divider):** Горизонтальная линия или пустое пространство (Spacer)

**Текстовые блоки:**
- **Заголовок (Heading):** H1-H6 с настройкой типографики
- **Параграф (Paragraph):** Обычный текст с форматированием
- **Список (List):** Маркированный или нумерованный
- **Цитата (Blockquote):** Стилизованная цитата

**Медиа-блоки:**
- **Изображение (Image):** Загрузка файла или URL, настройки `object-fit`, `alt` текст
- **Видео (Video):** HTML5 video или embed YouTube/Vimeo
- **Галерея (Gallery):** Сетка изображений с lightbox

**Интерактивные блоки:**
- **Кнопка (Button):** Текст, ссылка (URL или якорь на виртуальную страницу), стили, hover-эффекты
- **Форма (Form):** Поля (текст, email, телефон, textarea), кнопка отправки
- **Навигационное меню (Nav):** Автоматически генерирует ссылки на виртуальные страницы

#### 3.2.4. Панель настроек блоков (справа)

**Вкладка "Стили":**
- **Типографика:** Шрифт, размер, вес, межстрочный интервал, выравнивание, цвет
- **Фон:** Цвет, градиент, изображение (с настройками `background-size`, `background-position`)
- **Отступы:** Padding и Margin через визуальный контроллер (как в Figma)
- **Границы:** Border (ширина, стиль, цвет), Border-radius
- **Тени:** Box-shadow (X, Y, blur, spread, color)
- **Эффекты:** Прозрачность (opacity), трансформации (rotate, scale)

**Вкладка "Контент":**
- Редактирование текста (inline-редактор или textarea)
- Загрузка/замена изображений
- Настройка ссылок (для кнопок)
- Настройка полей формы

**Вкладка "Анимации":**
- Анимация появления (fade-in, slide-up, zoom-in)
- Задержка и длительность анимации
- Hover-эффекты (изменение цвета, масштаб)

**Вкладка "Адаптивность":**
- Переключатель: Desktop / Tablet / Mobile
- Настройка стилей для каждого устройства (переопределение десктопных стилей)
- Скрытие/показ блока на определенных устройствах

#### 3.2.5. Drag-and-Drop система
- Перетаскивание блоков из библиотеки на холст
- Изменение порядка блоков внутри секции

#### 3.3.3. Генерация виртуальных страниц (для обоих профилей)

**HTML-структура:**
```html
<!-- Сквозной Header -->
<header class="global-header">
  <nav>
    <a href="#home" class="nav-link active">Главная</a>
    <a href="#services" class="nav-link">Услуги</a>
    <a href="#contacts" class="nav-link">Контакты</a>
  </nav>
</header>

<!-- Виртуальные страницы -->
<main>
  <div data-virtual-page="home" class="v-page active">
    <!-- Контент главной страницы -->
  </div>
  
  <div data-virtual-page="services" class="v-page">
    <!-- Контент страницы услуг -->
  </div>
  
  <div data-virtual-page="contacts" class="v-page">
    <!-- Контент страницы контактов -->
  </div>
</main>

<!-- Сквозной Footer -->
<footer class="global-footer">
  <!-- Контент футера -->
</footer>
```

**CSS-логика:**
```css
.v-page {
  display: none; /* Все страницы скрыты по умолчанию */
}

.v-page.active {
  display: block; /* Активная страница видна */
}
```

**JavaScript-логика (экспортируется в `main.js`):**
```javascript
// Микро-скрипт для навигации между виртуальными страницами (~2 КБ)
document.addEventListener('DOMContentLoaded', () => {
  const navLinks = document.querySelectorAll('.nav-link');
  const pages = document.querySelectorAll('.v-page');
  
  // Функция переключения страниц
  function switchPage(pageId) {
    pages.forEach(page => {
      page.classList.remove('active');
      if (page.dataset.virtualPage === pageId) {
        page.classList.add('active');
      }
    });
    
    // Обновление активного состояния в меню
    navLinks.forEach(link => {
      link.classList.remove('active');
      if (link.getAttribute('href') === `#${pageId}`) {
        link.classList.add('active');
      }
    });
    
    // Обновление URL (hash-роутинг)
    history.pushState(null, '', `#${pageId}`);
    
    // Обновление <title> и <meta description> (если заданы для страницы)
    updateSEO(pageId);
    
    // Прокрутка наверх
    window.scrollTo(0, 0);
  }
  
  // Обработка кликов по меню
  navLinks.forEach(link => {
    link.addEventListener('click', (e) => {
      e.preventDefault();
      const pageId = link.getAttribute('href').substring(1);
      switchPage(pageId);
    });
  });
  
  // Обработка кнопки "Назад" в браузере
  window.addEventListener('popstate', () => {
    const pageId = window.location.hash.substring(1) || 'home';
    switchPage(pageId);
  });
  
  // Инициализация: показ страницы из URL или главной
  const initialPage = window.location.hash.substring(1) || 'home';
  switchPage(initialPage);
});

// Функция обновления SEO-тегов
function updateSEO(pageId) {
  const pageData = window.virtualPagesData[pageId];
  if (pageData) {
    document.title = pageData.title || document.title;
    const metaDesc = document.querySelector('meta[name="description"]');
    if (metaDesc && pageData.description) {
      metaDesc.setAttribute('content', pageData.description);
    }
  }
}
```

**Дополнительные фичи для виртуальных страниц:**
- ✅ **Плавные переходы:** CSS-анимации при переключении страниц (fade-in, slide-up)
- ✅ **Deep Linking:** Прямая ссылка на конкретную страницу (`mysite.html#contacts`)
- ✅ **История браузера:** Кнопки "Назад"/"Вперед" работают корректно
- ✅ **Динамическое SEO:** `<title>` и `<meta description>` меняются при переключении страниц
- ✅ **Ленивая загрузка медиа:** Картинки в неактивных страницах не грузятся сразу (используется `data-src` и Intersection Observer)

#### 3.3.4. Офлайн-формы (для локальных сайтов)

**Настройки формы в редакторе:**
- Выбор действия при отправке:
  1. **Скачать файл:** Данные формы скачиваются как `.json`, `.csv` или `.pdf`
  2. **Открыть почту:** Формируется `mailto:` ссылка с данными в теле письма
  3. **Показать сообщение:** Просто показать "Спасибо за обращение!" (без отправки)

**Генерируемый JavaScript:**
```javascript
// Пример для действия "Скачать JSON"
form.addEventListener('submit', (e) => {
  e.preventDefault();
  const formData = new FormData(form);
  const data = Object.fromEntries(formData.entries());
  
  const blob = new Blob([JSON.stringify(data, null, 2)], { type: 'application/json' });
  const url = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = 'form-data.json';
  a.click();
  URL.revokeObjectURL(url);
  
  alert('Данные сохранены!');
});
```

## 4. ТЕХНИЧЕСКИЕ ТРЕБОВАНИЯ

### 4.1. Технологический стек

**Frontend (Редактор):**
- **Фреймворк:** React 18+ или Vue 3 (предпочтительно React из-за экосистемы)
- **Drag-and-Drop:** `dnd-kit` (React) или `vuedraggable` (Vue)
- **Состояние:** Zustand (React) или Pinia (Vue)
- **Стили:** Tailwind CSS или CSS Modules
- **Редактор текста:** TipTap или Slate.js (для inline-редактирования)

**Backend:**
- **Фреймворк:** Node.js + NestJS или Fastify
- **База данных:** PostgreSQL (хранение JSON-деревьев проектов)
- **ORM:** Prisma или TypeORM
- **Аутентификация:** JWT + refresh tokens
- **Валидация:** Zod или Joi

**Хранилище медиа:**
- **Основное:** Cloudflare R2 (дешевле AWS S3, нет платы за исходящий трафик)
- **Альтернатива:** AWS S3 или MinIO (self-hosted)

**Генерация экспорта:**
- **HTML/CSS генератор:** Кастомный рендерер на Node.js (читает JSON, генерирует HTML)
- **ZIP-архиватор:** `archiver` (Node.js) или `JSZip` (можно делать на фронтенде)
- **Оптимизация изображений:** `sharp` (Node.js) для конвертации в WebP и сжатия
- **Минификация:** `html-minifier`, `clean-css`, `terser`

**Инфраструктура:**
- **Хостинг:** Vercel (фронтенд) + Railway/Render (бэкенд)
- **CI/CD:** GitHub Actions
- **Мониторинг:** Sentry (ошибки), LogRocket (UX-аналитика)

### 4.2. Требования к производительности

**Редактор:**
- Время загрузки интерфейса: < 2 секунды
- Плавность Drag-and-Drop: 60 FPS
- Время отклика на изменения стилей: < 100 мс

**Экспорт:**
- Генерация Single HTML (без медиа): < 3 секунды
- Генерация Single HTML (с 50 картинками): < 30 секунд
- Генерация ZIP-архива: < 10 секунд

**Сайт на выходе:**
- Размер Single HTML (без медиа): < 500 КБ
- Размер Single HTML (с 10 картинками): < 5 МБ
- Время загрузки (Lighthouse Performance): > 90 баллов

### 4.3. Требования к безопасности

**Аутентификация:**
- Хеширование паролей: bcrypt (salt rounds: 12)
- JWT токены: срок жизни access token — 15 минут, refresh token — 7 дней
- Защита от CSRF: SameSite cookies + CSRF tokens

**Защита данных:**
- Валидация всех входных данных (Zod/Joi)
- Защита от XSS: санитизация HTML-контента (библиотека `DOMPurify`)
- Защита от SQL-инъекций: использование ORM (Prisma)
- Rate limiting: 100 запросов в минуту на пользователя

**Экспорт:**
- Проверка размера файла перед генерацией (максимум 100 МБ)
- Ограничение количества блоков в проекте (максимум 500)
- Валидация загружаемых файлов (проверка MIME-типа, антивирусная проверка)

## 6. ТЕХНИЧЕСКИЕ РИСКИ И РЕШЕНИЯ

### Риск 1: "Мусорный" код на выходе
**Проблема:** Многие конструкторы генерируют HTML с множеством лишних `<div>` и абсолютным позиционированием.

**Решение:**
- Жестко регламентировать JSON-схему (избегать лишних оберток)
- Использовать только Flexbox/Grid (никаких `float` или `position: absolute` для сетки)
- Писать unit-тесты на рендерер: сравнивать выходной HTML с эталонным чистым кодом
- Ручная проверка качества кода на первых релизах

### Риск 2: Раздувание Single HTML файла
**Проблема:** Картинки в Base64 могут увеличить файл до 50-100 МБ.

**Решение:**
- Автоматическая конвертация всех картинок в WebP (уменьшение в 3-5 раз)
- Сжатие до 80% качества (невидимо для глаза)
- Предупреждение пользователя, если файл превышает 20 МБ
- Альтернатива: в Single HTML оставлять ссылки на картинки (если выбран профиль "Для интернета")

### Риск 3: Дублирование ID в виртуальных страницах
**Проблема:** Если пользователь на разных страницах использует одинаковые ID, HTML будет невалидным.

**Решение:**
- Запретить задавать кастомные ID в редакторе
- При экспорте автоматически добавлять префикс страницы к каждому ID (например, `page-services__submit-btn`)
- Валидация HTML через W3C Validator после генерации

### Риск 4: Сложность реализации форм для офлайн-режима
**Проблема:** Формы не могут отправлять данные на сервер, если сайт открыт локально.

**Решение:**
- Предложить 3 варианта действия (скачать файл, mailto, показать сообщение)
- Четко объяснить пользователю ограничения офлайн-форм в интерфейсе
- Для профиля "Для интернета" использовать стандартный `action="..."` или интеграцию с Formspree

### Риск 5: Производительность редактора при большом количестве блоков
**Проблема:** Если пользователь добавит 200+ блоков, редактор может тормозить.

**Решение:**
- Виртуализация списка блоков (рендерить только видимые блоки)
- Debounce для сохранения изменений (сохранять не чаще раза в 500 мс)
- Ограничение максимального количества блоков (500)
- Оптимизация React-компонентов (React.memo, useMemo)

## 8. ЗАКЛЮЧЕНИЕ

Данное техническое задание описывает платформу для создания сайтов с уникальным преимуществом — **полной автономностью экспортируемых файлов**. Пользователи получают не просто ссылки на хостинг, а готовые HTML-файлы или ZIP-архивы, которые можно:
- Отправить клиенту в мессенджере
- Открыть на компьютере без интернета
- Разместить на любом хостинге
- Доработать в редакторе кода

Ключевые фичи, которые делают продукт уникальным:
1. **Виртуальные страницы в одном файле** — многостраничник без серверного роутинга
2. **Полный офлайн-режим** — шрифты, иконки, картинки встраиваются в код
3. **Офлайн-формы** — данные сохраняются локально или отправляются через mailto
4. **Режим презентации** — сайт как интерактивный слайд-шоу
5. **Чистый код на выходе** — семантичный HTML5, современный CSS3, ванильный JS

Продукт занимает нишу между классическими конструкторами (Tilda, Wix) и генераторами презентаций (PowerPoint, Canva), предлагая уникальный инструмент для **direct-share сайтов** и **локальной документации**.
